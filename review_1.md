## 4. Top 5 To Fix Before Any Real Production Call Volume

1. **Rotate the leaked Neon DB credential in `.env.example` (C1) immediately** — this is a live
   secret in git history right now, independent of anything else.
2. **Put real authentication + rate limiting on all three API routes, and stop the unauthenticated
   PII bulk-read on `GET /calls/results` (C2)** — today, anyone who can reach the port can place
   arbitrary robocalls and read every recent owner's phone number, name, and transcript.
3. **Add a pre-dispatch dedupe/cooldown check for `(property_id, phone_number)` (C3)** — nothing
   currently stops the same owner from being called repeatedly, which is both a user-experience and
   regulatory (C8) problem.
4. **Make provider/session failures actually terminal**: wire `AgentSessionEventTypes.Error` to a
   real failure path instead of log-only (C4), fix the `SIP_OUTBOUND_TRUNK_ID`-unset silent hang
   (C5), and add `.catch()` + a process-level `unhandledRejection`/`uncaughtException` handler so one
   bad call can't crash the whole worker and every concurrent call with it (C6).
5. **Close the PII exposure gap**: encrypt or access-restrict the `phone_number`/`owner_name`/
   `transcript` columns and `call_results/*.json` files, and actually wire up `CALL_DEBUG_LOGGING`
   so verbatim transcript logging can be turned off as the docs already claim (C9) — and treat C8
   (TRAI/DND) as a blocking business/legal question to resolve with stakeholders before scaling call
   volume, not just a code follow-up.
